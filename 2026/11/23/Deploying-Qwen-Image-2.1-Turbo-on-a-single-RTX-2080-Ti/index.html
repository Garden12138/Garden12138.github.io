Deploying Qwen-Image-2.1-Turbo on a single RTX 2080 Ti

发表于2026-11-23|更新于2026-11-23
|浏览量:

使用单张 RTX 2080 Ti 部署 Qwen-Image-2.1-Turbo 本地生图服务

目标

  • 在一台 Ubuntu 服务器（单张 RTX 2080 Ti 22GB）上本地运行 Qwen-Image-2.1-Turbo，实现三种能力：

    • 文生图：输入提示词生成图片。
    • 整图编辑：上传一张图片，用文字描述要修改的内容。
    • 局部涂抹编辑：在图片上涂出要修改的区域，只修改这一部分。

  • 提供两种使用方式：

    • 浏览器打开 Web 工作台直接使用。
    • 通过兼容 OpenAI Images API 的接口，供 Python 程序或 AI Agent 调用。

方案说明

22GB 显存放不下完整精度的模型，因此采用以下组合：

  • 模型：Qwen-Image-2.1-Turbo 的 Q4_K_M GGUF 量化版本。量化后体积和显存占用大幅降低，Turbo 版本只需 8 步采样，速度较快。
  • 推理引擎：stable-diffusion.cpp，一个 C/C++ 实现的扩散模型推理引擎，支持 GGUF 和 CUDA，并自带 HTTP 服务程序 sd-server。
  • 服务层：用 FastAPI 编写一个工作台网关，负责参数校验、任务排队和提供网页；再编写一个适配层，把接口包装成 OpenAI Images API 格式。

最终由三个进程组成，调用关系如下：

进程 监听地址 作用
sd-server 127.0.0.1:1234 加载模型并执行推理，只允许本机访问
工作台 qwen_image_gateway.py 0.0.0.0:8000 提供网页和生成、编辑接口，同一时间只执行一个任务，不鉴权
适配层 openai_compat_gateway.py 0.0.0.0:8001 OpenAI Images API 兼容接口，使用 Bearer Token 鉴权

建议按 命令行生图 → sd-server → Web 工作台 → API 适配层 的顺序逐层搭建，每层验证通过后再进行下一层，出问题时容易判断是哪一层的原因。

  • 开启 CUDA 编译。RTX 2080 Ti 是 Turing 架构，计算能力 7.5，所以 CMAKE_CUDA_ARCHITECTURES 设为 75：

    编译过程中出现的 warning 可以忽略，只要最后链接成功即可。并行数 -j 不宜设置过大，避免内存不足。

  • 为什么要加 --strength 1：一开始编辑图片时，“把白衣服改成红色”可以成功，但“剪短头发”“添加人物”几乎没有效果。原因是当前版本的 /v1/images/edits 会走 img2img 流程（参考 Issue #1779），把默认 --strength 设为 1 可以绕过这个问题。升级引擎版本后需要重新验证是否还需要这个参数。

  • 为什么只监听 127.0.0.1：sd-server 没有鉴权、排队和参数校验，不应直接对外开放。对外统一由后面的工作台和适配层提供服务。

    编辑前 局部编辑后

  • 使用经验：

    • 遮罩只限定“允许修改的区域”，区域内画什么仍由模型决定，不是 Photoshop 式的精确替换。
    • 把长发改短发时，肩膀和胸前没涂到的发丝可能残留。解决办法是把涂抹范围扩大到所有需要重绘的位置。

关于 1024×1024

  • 工作台支持 1024×1024，但这个尺寸曾导致整机卡死，至今没有稳定性验证，因此默认关闭。

  • 1024×1024 的像素数约为 768×768 的 1.8 倍，--max-vram 和 CPU Offload 能降低显存占用，但无法消除显存和内存的峰值。

  • 如果要测试：先停止其他 GPU 任务，每次只生成一张，并做好机器卡死后的恢复准备。

Agent 配置建议

配置项 建议值
Base URL http://<SERVER_IP>:8001/v1
Model qwen-image-2.1-turbo
Size 768x768（/health 返回的 allowed_sizes 包含 1024 时才使用 1024）
Timeout 不低于 660 秒
Max retries 0，由 Agent 按错误码决定是否重试
并发 同一时间只提交一个任务

  • 常见错误码：

    状态码 原因 处理方式
    400 参数、尺寸不支持，遮罩尺寸不一致，n 不为 1 修正请求
    401 API Key 缺失或错误 检查 Authorization: Bearer ...
    413 / 415 图片超过 20 MiB，或不是 PNG/JPEG/WebP 压缩或转换格式
    429 排队已满（1 个执行中 + 最多 2 个等待） 等待 5～15 秒后重试
    501 调用了聊天接口 改用 Images API
    502 / 503 工作台未启动或未就绪 检查 8000 服务和 /health
    504 推理超时 先确认原任务是否还在执行，不要立即重复提交

    完整的对接说明见 AGENT_INTEGRATION.md。

安全注意事项

  • 1234 只监听本机，不要对外开放。
  • 8000 工作台不鉴权。即使 8001 设置了 API Key，能直接访问 8000 也等于绕过了鉴权，只能在可信局域网中使用。
  • 跨网段或公网访问时，需要通过防火墙限制来源 IP，并使用 HTTPS 或 VPN。
  • .env.openai-image、模型文件、日志不要提交到 Git；API Key 不要写进前端页面或 Agent 的提示词。
